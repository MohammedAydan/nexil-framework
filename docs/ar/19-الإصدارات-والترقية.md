# 19 — الإصدارات والترقية

## سياسة الإصدار

ثبّت إصدار Nexis في `package.json` وlockfile، ولا تعتمد على `latest` في CI. الإصدار الرئيسي قد يغير public API أو build artifact أو contract بين Compiler وBootstrap؛ لذلك يجب ترقية الحزم المتصلة معًا.

## قبل الترقية

احفظ:

- commit مستقر.
- نتائج `pnpm test` و`pnpm build`.
- benchmark artifacts.
- نسخة من `nexis.config`.
- نسخة من generated output إذا كان النشر يتطلب rollback.

اقرأ CHANGELOG وملفات ADR وراجع تغييرات الحزم التي تستخدمها مباشرة.

## الترقية داخل workspace

```bash
pnpm install --offline --no-frozen-lockfile
pnpm build
pnpm typecheck
pnpm test
```

في مشروع مستقل، استخدم lockfile جديدًا فقط عند قصدك تحديث dependencies، ثم راجع diff وليس عدد الحزم فقط.

## ترتيب التحقق

1. TypeScript contracts.
2. Compiler/Vite plugin.
3. Renderer وClient bootstrap.
4. CLI build.
5. Production server.
6. E2E browser.
7. Lighthouse وbudget.
8. Security audit.

إذا تغير Bootstrap، لا تكتفِ باختبار unit؛ شغّل browser E2E وراجع lazy chunks.

## أمثلة تغييرات حساسة

| التغيير                | ما يجب اختباره                         |
| ---------------------- | -------------------------------------- |
| تغيير ScopeRef         | registry round-trip وcomponent capture |
| تغيير route matcher    | كل routes و404 وdynamic paths          |
| تغيير render mode      | cache headers وSSR/ISR behavior        |
| تغيير action transport | Origin وreplay وforms وJSON            |
| تغيير CSS pipeline     | static JS floor وvisual QA             |
| تغيير SEO              | كل head وsitemap/feed وdangerous URLs  |
| تغيير server           | GET/HEAD/405/404/traversal             |

## التراجع

إذا فشل release بعد النشر، أعد build السابق بدل تعديل ملفات `dist` يدويًا. احتفظ بـ artifact قابل لإعادة النشر، وراجع إن كان الخطأ من source أو environment أو proxy.

## ترقية v1.0.0

في v1.0.0 أضيفت حزم OG وCloudflare وDeno، وfeed Atom، وLighthouse وAstro comparison، وtyped config، وincremental stream، وmedia persistent cache، وWeb Vitals observers. يجب أن يراجع التطبيق أي إعداد cache أو telemetry أو proxy عند الترقية.

## التوافق

لا تخلط `@mohammedaydan/renderer` من إصدار مع `@mohammedaydan/vite-plugin` من إصدار مختلف إذا كان contract الـ bootstrap تغير. استخدم مجموعة متناسقة من الإصدار نفسه.

## تعريف Done للترقية

الترقية مكتملة فقط عندما:

- build وtypecheck ينجحان.
- unit/integration/E2E تمر.
- Deno الحقيقي يمر في CI إن كان runtime مستهدفًا.
- Lighthouse وbudget لا يتراجعان.
- security audit لا يظهر high severity غير معالج.
- docs وrelease notes محدثة.
- migration وrollback معروفان.
