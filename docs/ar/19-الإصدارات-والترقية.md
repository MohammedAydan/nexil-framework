# 19 — الإصدارات والترقية

## سياسة الإصدار

ثبّت إصدار Nexil في `package.json` وlockfile، ولا تعتمد على `latest` في CI. الإصدار الرئيسي قد يغير public API أو build artifact أو contract بين Compiler وBootstrap؛ لذلك يجب ترقية الحزم المتصلة معًا.

## قبل الترقية

احفظ:

- commit مستقر.
- نتائج `pnpm test` و`pnpm build`.
- benchmark artifacts.
- نسخة من `nexil.config`.
- نسخة من generated output إذا كان النشر يتطلب rollback.

اقرأ CHANGELOG وملفات ADR وراجع تغييرات الحزم التي تستخدمها مباشرة.

## الترقية داخل workspace

```bash
pnpm install --offline --no-frozen-lockfile
pnpm build
pnpm typecheck
pnpm test
```

في مشروع مستقل، استخدم lockfile جديدًا فقط عند قصدك تحديث dependencies، ثم راجع diff وليس عدد الحزم فقط.

## ترتيب التحقق

1. TypeScript contracts.
2. Compiler/Vite plugin.
3. Renderer وClient bootstrap.
4. CLI build.
5. Production server.
6. E2E browser.
7. Lighthouse وbudget.
8. Security audit.

إذا تغير Bootstrap، لا تكتفِ باختبار unit؛ شغّل browser E2E وراجع lazy chunks.

## أمثلة تغييرات حساسة

| التغيير                | ما يجب اختباره                                  |
| ---------------------- | ----------------------------------------------- |
| تغيير ScopeRef         | registry round-trip وcomponent capture          |
| تغيير route matcher    | كل routes و404 وdynamic paths                   |
| تغيير render mode      | cache headers وSSR/ISR behavior                 |
| تغيير action transport | Origin وreplay وforms وJSON                     |
| تغيير CSS pipeline     | static JS floor وvisual QA                      |
| تغيير SEO              | كل head وsitemap/feed وdangerous URLs           |
| تغيير server           | GET/HEAD/405/404/traversal                      |
| تغيير layouts          | `_layout.*` وroute groups وmetadata inheritance |
| تغيير Suspense/stream  | fallback وout-of-order boundaries               |
| تغيير forms            | native fallback وforms runtime وfields المتكررة |

## الترقية إلى v1.1.0

عند الانتقال من v1.0.0 إلى v1.1.0، استخدم `_layout.*` للتخطيطات الجديدة، وأزل `serializeScopeRefs()` اليدوي من route components، واستخرج الأغلفة المتكررة إلى root أو nested layouts. حدّث فحوص المخرجات لتشمل `nexil-forms.js` و`nexil-chunks/` وتوارث metadata وقوالب Suspense.

استخدم `Form` و`SubmitButton` للنماذج، وأضف `endpoint` إلى action عند تمرير مرجع Action، مع إبقاء التحقق والتفويض وOrigin وCSRF وidempotency على الخادم. تبقى ملفات `layout.*` مدعومة للتوافق.

## الترقية إلى v1.2.0

حدّث حزم Nexil المتناسقة إلى `1.2.0` في تعديل dependencies واحد، وجدد lockfile، ثم نفّذ build نظيفًا. لا تخلط خصوصًا بين `@nexil/cli` أو `@nexil/vite-plugin` قديم وartifact مولد من v1.2.0: الصفحات التفاعلية في production تستخدم الآن مفاتيح `data-nx-scope` معتمة وملف `nexil-state.js` مشروط.

بعد الترقية، أعد البناء من source، وتحقق أن Routes الثابتة لا تخرج state runtime، واستخدم Playwright للتحقق أن Route تفاعليًا يحمل `nexil-state.js` ويحافظ على مفاتيح scope المعتمة داخل DOM ويستأنف handlers وbindings معًا. أصل state العام ليس مخزن أسرار؛ أزل أي capture حساس بدل الاعتماد على شكل HTML الجديد.

يمكن لإنشاء المشروع الآن اختيار `minimal` أو `interactive` أو `secure-node` عبر `--template`؛ يبقى سلوك المنشئ الافتراضي هو `interactive`. شغّل `nexil doctor --json` داخل CI عندما تريد تقرير تهيئة مُرقمًا، مع اعتبار تحذيراته prompts للمراجعة وليس attestations للبنية التحتية.

## الترقية إلى v1.3.0

حدّث مجموعة حزم Nexil المتناسقة كلها إلى `1.3.0` في تعديل dependencies واحد، بما فيها `@nexil/seo`، وجدّد lockfile، واحذف مخرجات `dist` السابقة ثم ابنِ من جديد. لا تخلط CLI أو Router أو Vite plugin أو resumability runtime من v1.2 مع artifact إنتاج مولد من v1.3.

استعمل `Link` للتنقل الداخلي المؤهل عندما يناسبك استبدال منفذ `#app` مباشرة. أبقِ `href` صالحًا بلا JavaScript، وتأكد أن كل وجهة صحيحة كـHTML مستقل من SSR/SSG. يبقى تنقل hash-only والنقرة المعدّلة وmiddle-click والروابط الخارجية و`target` و`download` و`rel="external"` تنقلاً أصليًا؛ ويتحول fetch الفاشل أو الرد غير HTML أو وثيقة الوجهة الناقصة إلى تنقل عادي. تعامل مع `prefetch` كتلميح محدود للبيانات العامة في ذاكرة جلسة المتصفح، لا كـdata cache: لا تُحتفَظ ردود `private` و`no-store`.

توفّر `createContextScope` و`provideContext` و`withContext` dependency injection صريحًا وآمنًا للطلب خلال SSR/SSG. مرّر scope صراحةً عبر العمل غير المتزامن. Context لا يسرّل حالة إلى العميل ولا يجعل القيمة خاصة في المتصفح. إذا احتجت بقاء الحالة خلال Link مؤهل داخل document متصفح واحد، عرّف `createStore(initial, 'global')`؛ تظل الحالة عامة في المتصفح، وتُصفّر عند إعادة تحميل document، ولا يجب أن تحتوي secrets.

## الترقية إلى v1.3.1

حدّث حزم Nexil المتناسقة إلى `1.3.1` معًا وجدّد lockfile. يغير هذا التصحيح نطاق dependencies الافتراضي المولد من Starter من `^1.2.0` إلى `^1.3.1`؛ ولا يحتاج التطبيق الموجود الذي ثبّت `1.3.0` عمدًا إلى تعديل source.

## التراجع

إذا فشل release بعد النشر، أعد build السابق بدل تعديل ملفات `dist` يدويًا. احتفظ بـ artifact قابل لإعادة النشر، وراجع إن كان الخطأ من source أو environment أو proxy.

## ترقية v1.0.0

في v1.0.0 أضيفت حزم OG وCloudflare وDeno، وfeed Atom، وLighthouse وAstro comparison، وtyped config، وincremental stream، وmedia persistent cache، وWeb Vitals observers. في v1.1.0 أضيفت automatic lowering وscope deduplication وnested layouts وmetadata inheritance وSuspense streaming وprogressive forms وtyped loaders وأوامر CLI إضافية. راجع [ملاحظات v1.1.0](../releases/v1.1.0-ar.md).

## التوافق

لا تخلط `@nexil/renderer` من إصدار مع `@nexil/vite-plugin` من إصدار مختلف إذا كان contract الـ bootstrap تغير. استخدم مجموعة متناسقة من الإصدار نفسه.

## تعريف Done للترقية

الترقية مكتملة فقط عندما:

- build وtypecheck ينجحان.
- unit/integration/E2E تمر.
- Deno الحقيقي يمر في CI إن كان runtime مستهدفًا.
- Lighthouse وbudget لا يتراجعان.
- security audit لا يظهر high severity غير معالج.
- docs وrelease notes محدثة.
- migration وrollback معروفان.
