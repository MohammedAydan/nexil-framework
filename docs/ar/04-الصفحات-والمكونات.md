# 04 — الصفحات والمكونات

## الصفحة Route

الصفحة هي وحدة URL ومسؤولة عن تركيب المحتوى والبيانات والـ metadata وحدود التفاعل. اجعل Route رفيعًا: يستدعي طبقة البيانات، يمرر النتائج إلى مكونات، ويحدد metadata وrender mode.

```tsx
// src/routes/products.tsx
import { ProductGrid } from '../components/ProductGrid.js'
import { getProducts } from '../lib/server/products.js'

export default async function ProductsPage() {
  const products = await getProducts()
  return (
    <main>
      <h1>المنتجات</h1>
      <ProductGrid products={products} />
    </main>
  )
}
```

## المكون الساكن

المكون الساكن لا يملك أحداثًا أو Signals أو Browser APIs. اكتب فيه markup فقط، واجعله قابلًا لإعادة الاستخدام.

```tsx
interface CardProps {
  readonly title: string
  readonly description: string
  readonly href: string
}

export function Card({ title, description, href }: CardProps) {
  return (
    <article className="card">
      <h2>
        <a href={href}>{title}</a>
      </h2>
      <p>{description}</p>
    </article>
  )
}
```

## المكون المتفاعل

المكون المتفاعل يجب أن يكون صغيرًا ومحددًا. لا تجعل Layout كاملًا تفاعليًا بسبب زر واحد؛ افصل الزر في مكون مستقل واستخدم Handler lazy.

```tsx
import { state } from '@mohammedaydan/reactivity'

export function Counter() {
  const count = state(0)
  return (
    <button
      data-nx-state={count.value}
      onClick$={() => {
        count.set((previous) => previous + 1)
      }}
    >
      Count: {count.value}
    </button>
  )
}
```

في الكود الذي يعتمده Compiler، لاحقة `$` هي إشارة إلى أن السلوك يجب أن يكون قابلًا للتحليل والإخراج في lazy chunk. لا تضع Closure ضخمة داخل Handler؛ استخرج المنطق إلى وظيفة صغيرة ومرر قيمًا قابلة للتسلسل.

## Props

عرّف Props بـ `interface`، واستخدم `readonly` للقيم التي لا يعدلها المكون. تحقق من البيانات القادمة من المستخدم أو من API قبل تمريرها إلى markup.

```tsx
interface UserBadgeProps {
  readonly name: string
  readonly role?: string
}

export function UserBadge({ name, role = 'member' }: UserBadgeProps) {
  return (
    <span aria-label={`المستخدم ${name}`}>
      {name} — {role}
    </span>
  )
}
```

## Async components

يمكن أن يكون Route أو مكونًا خادميًا `async` إذا احتاج إلى بيانات. لا تجعل Promise يصل إلى DOM دون أن يمر عبر Renderer الذي يدعم `renderChildAsync`.

```tsx
export async function LatestPosts() {
  const posts = await loadLatestPosts()
  return (
    <ul>
      {posts.map((post) => (
        <li key={post.id}>{post.title}</li>
      ))}
    </ul>
  )
}
```

## المكونات المركبة

قسّم الصفحة إلى مناطق لها معنى: Header، Navigation، Main، Sidebar، Footer. لا تفرط في تقسيم كل `<div>` إلى ملف. المكون الجيد يعزل مسؤولية واضحة ويملك واجهة Props مستقرة.

## قواعد كتابة جيدة

| القاعدة           | التطبيق                                             |
| ----------------- | --------------------------------------------------- |
| HTML أولًا        | أخرج المحتوى الأساسي دون انتظار JavaScript          |
| تفاعل محلي        | ضع `$` على أصغر Handler ممكن                        |
| بيانات منضبطة     | عرّف أنواع نتائج API قبل عرضها                      |
| لا أسرار في Props | لا تمرر مفاتيح أو tokens إلى JSX                    |
| Accessibility     | استخدم عناصر HTML الصحيحة وLabels وKeyboard support |
| روابط حقيقية      | استخدم `<a href>` للتنقل وprogressive enhancement   |
| أداء              | لا تشحن مكتبة كبيرة لزر بسيط                        |

## الوصولية

استخدم `button` للأفعال و`a` للانتقال. أضف `label` لكل input، واستخدم `aria-live` لمخرجات الطلبات غير المتزامنة، ولا تعتمد على color وحده لشرح الحالة. اختبر لوحة المفاتيح وViewport ضيقًا في Playwright.

## الأخطاء الشائعة

- جعل كل الصفحة تفاعلية لأن جزءًا صغيرًا يحتاج إلى state.
- وضع fetch وdatabase داخل مكون يُحتمل أن يدخل bundle العميل.
- تمرير object معقد أو Closure إلى `ScopeRef` ثم توقع أن يعاد بناؤه تلقائيًا.
- استخدام `innerHTML` مع نص قادم من المستخدم.
- إنشاء Link مخصص لا يعمل قبل تحميل JavaScript بدل استخدام `<a>`.
