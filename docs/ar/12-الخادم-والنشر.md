# 12 — الخادم والنشر

## اختيار بيئة التشغيل

| البيئة     | الحزمة                    | متى تستخدمها                        |
| ---------- | ------------------------- | ----------------------------------- |
| Node       | `@nexil/serve`            | خادم إنتاج كامل على VM أو container |
| Deno       | `@nexil/serve-deno`       | Fetch-native runtime وDeno Deploy   |
| Cloudflare | `@nexil/serve-cloudflare` | Workers مع Assets binding           |
| Dev        | `@nexil/dev-server`       | التطوير المحلي فقط                  |

ابنِ التطبيق مرة واحدة، ثم اختر Adapter يطابق عقد Request/Response وبيئة النشر.

## بناء الإنتاج

```bash
pnpm install --frozen-lockfile
pnpm build
```

افحص وجود `dist/client/index.html` و`nexil-manifest.json` و`nexil-bootstrap.js` عند وجود routes تفاعلية، ووجود `sitemap.xml` و`robots.txt` و`feed.xml` و`atom.xml`.

## Node production server

```ts
import { createServer } from '@nexil/serve'

const app = createServer('./dist/client', {
  host: process.env.HOST ?? '0.0.0.0',
  port: Number(process.env.PORT ?? 3000),
  redirects: [{ from: '/docs', to: '/docs/architecture', status: 308 }],
  // فعّلها فقط عندما ينظف reverse proxy الموثوق forwarded headers القادمة من العميل.
  trustProxy: process.env.DEPLOYMENT_TRUST_PROXY === 'true',
  securityHeaders: {
    contentSecurityPolicy: "default-src 'self'; base-uri 'self'; frame-ancestors 'none'",
    // أضف HSTS فقط إن كانت نقطة إنهاء TLS معروفة وكل النطاقات HTTPS فعلًا.
    strictTransportSecurity: 'max-age=31536000; includeSubDomains',
  },
})

await app.listen()
```

الخادم الرسمي يطبق route mapping، 404، 405، HEAD، MIME، cache headers، traversal rejection، action delegation، وtelemetry receiver اختياري.

## Deno

`createDenoHandler` يعطي Fetch handler، و`serveDeno` يستدعي `Deno.serve` في runtime Deno. ضع asset map أو delegate route handler حسب التطبيق.

```ts
const handler = createDenoHandler({
  assets: {
    '/index.html': { body: '<h1>Home</h1>', contentType: 'text/html' },
  },
  fallback: appHandler,
})
serveDeno(handler)
```

لا تستخدم `process` أو `fs` داخل المسار الذي يجب أن يعمل على Deno.

## Cloudflare

`createCloudflareHandler` يجرب Assets binding ثم يمرر الطلب إلى fallback handler. لا تفترض اسم binding ثابتًا؛ مرر الواجهة التي يوفرها deployment.

```ts
const handler = createCloudflareHandler({
  assets: env.ASSETS,
  fallback: appHandler,
})
```

راجع حدود البيئة مثل CPU time، حجم الاستجابة، والـ storage؛ لا تنقل سلوك Node كما هو إلى Worker.

## Redirects

عرّف redirects محليًا فقط وبـ status مسموح. لا تسمح بـ `https://evil.test` أو protocol غير آمن. اختبر `redirect: 'manual'` حتى ترى `308` الحقيقي بدل أن يتبعه fetch تلقائيًا.

## Response security headers

خيار `securityHeaders` opt-in في خادم Node الإنتاجي. عند تفعيله يرسل
`X-Content-Type-Options: nosniff` و`X-Frame-Options: DENY` و
`Referrer-Policy: strict-origin-when-cross-origin` و`Permissions-Policy` مقيّدًا لكل
استجابة من Node، بما فيها assets وredirects وtelemetry والأخطاء وActions. لا غيّر
السياسات الافتراضية إلا بعد مراجعة واضحة.

`contentSecurityPolicy` و`strictTransportSecurity` opt-in عمدًا. راجع CSP مقابل
scripts وstyles وimages وconnections وembedding التي يحتاجها التطبيق فعلًا. لا أرسل
HSTS إلا إن كانت TLS termination مفهومة وكل hostname قابل للوصول جاهزًا لـ HTTPS.
القيم التي تحوي CR أو LF تُرفض.

## Proxy trust

اجعل `trustProxy: true` فقط خلف reverse proxy موثوق. يجب أن يزيل proxy headers التي
أدخلها العميل ثم يكتب قيمه الصحيحة. عندها يستخدم transport الخاص بـ Action أول
`x-forwarded-proto` و`x-forwarded-host` صالحين لإعادة بناء URL العام وتقييم Origin.
هذه headers تُتجاهل افتراضيًا. إذا كان التطبيق متاحًا مباشرة للإنترنت، لا تفعل هذا
الخيار.

## Cache

- HTML: `must-revalidate` أو سياسة مرتبطة بالبيانات.
- assets fingerprinted: `immutable` لمدة طويلة.
- actions: لا cache عامة.
- telemetry: لا cache.
- private response: `private` وعدم تخزينها في CDN مشترك.

## Health checks

أنشئ endpoint health منفصلًا عن صفحات المحتوى. health لا يجب أن يعتمد على JavaScript أو database query ثقيل. راقب status code، latency، memory، وعدد أخطاء actions.

## Containers

في container:

```dockerfile
FROM node:22-slim
WORKDIR /app
COPY package.json pnpm-lock.yaml ./
RUN corepack enable && pnpm install --frozen-lockfile
COPY . .
RUN pnpm build
EXPOSE 3000
CMD ["pnpm", "start"]
```

استخدم user غير root، وread-only filesystem متى أمكن، وحدد memory وCPU. لا تضع secrets داخل image.

## نشر آمن

قبل فتح المرور:

1. شغّل build من lockfile.
2. شغّل typecheck وtests وlint.
3. افحص sitemap وrobots وfeeds.
4. افحص redirect و404 و405 وHEAD.
5. تحقق من Origin وIdempotency في Actions، بما فيها رفض Action من Origin غير موثوق.
6. راجع CSP في متصفح واختبر cookies على HTTPS حقيقي.
7. راقب أول release مع rollback واضح.

## مختبر Workbench

يشغّل `pnpm --filter @nexil/example-nexil-workbench verify` TypeScript وفحص Nexil budget وproduction build للمثال الكامل. ابدأ artifact الناتج فقط عبر `pnpm --filter @nexil/example-nexil-workbench start`؛ لا تستخدم development server دليلًا للإنتاج. توضح server modules في Workbench integration boundaries وليست database أو identity provider أو durable session store مستضافة.
