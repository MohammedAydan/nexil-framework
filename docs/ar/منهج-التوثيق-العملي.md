# منهج التوثيق العملي

> **الحالة: خطة تنفيذ لفرع التوثيق الحالي.** هذا المنهج توثيق فقط؛ ولا يعني أن Nexil يوفر قاعدة بيانات أو مزود هوية مستضافًا أو مدفوعات أو تخزين تطبيق دائم.

## النتيجة المستهدفة

يجب أن يستطيع مطور أو AI agent لا يعرف Nexil إنشاء تطبيق HTML-first وفهمه واختباره ونشره وتشغيله دون تخمين سلوك الفريمورك. تتجه الدروس كلها إلى تطبيق واحد متماسك اسمه **Nexil Workbench**: قاعدة معرفة عامة فيها مقالات ثابتة، فلتر تفاعلي صغير، نموذج دعم native-first، وحدود جلسة وتفويض يملكها التطبيق، وبيانات وصفية للإنتاج، وعملية إصدار قابلة للتحقق.

## عقد كل درس

كل واجهة عامة في توثيق الفريمورك والموقع يجب أن تعرض العناصر الستة نفسها.

| العنصر           | المطلوب                                                                                    |
| ---------------- | ------------------------------------------------------------------------------------------ |
| الغرض            | شرح المشكلة التي تحلها الميزة ومتى لا تستخدمها.                                            |
| كود قابل للتشغيل | ملف أو أمر صغير متحقق من المصدر يمكن نسخه إلى الدرس الحالي.                                |
| عقد HTML-first   | ما الذي يظهر قبل JavaScript وما الذي يبقى native عند غياب التحسين.                         |
| حد الأمان        | حدود الملكية أو عزل الطلب أو البيانات العامة في المتصفح أو validation أو cache أو secrets. |
| التحقق           | الأمر والنتيجة المرئية، بما في ذلك artifact أو سلوك متصفح عند الحاجة.                      |
| مصدر مرتبط       | رابط الحزمة المالكة والمثال التنفيذي والاختبار المركز بدل اختراع API.                      |

## سياسة المصدر

يبقى توثيق الفريمورك المرجع المعياري الثنائي اللغة. الموقع الرسمي هو رفيق تعلّم يعرض المرجع نفسه، وليس إعادة كتابة مستقلة. يجب أن يدعم نموذج المحتوى القادم أكثر من code block واحد لكل دليل: أقسام **ابنِ** و**تحقق** و**حد الإنتاج** وملفات مختبر مرتبة. يجوز للموقع تلخيص النثر، لكنه لا يحذف أمرًا أو تحذيرًا أو رابط مصدر من الدليل المعياري.

## سياسة الأمثلة

استخدم واجهات Nexil الحقيقية فقط. عندما يحتاج التطبيق الكامل إلى تخزين أو بريد أو مزود هوية أو secret للنشر، عرّفه كواجهة يملكها التطبيق واشرح نقطة التكامل. لا تعرض placeholder وكأنه نظام مشحون مع الفريمورك. لا تضع credentials أو بيانات شخصية أو قرارات تفويض أو قيم خاصة بطلب في JSX أو HTML الناتج أو `nexil-state.js` أو client chunks أو الأمثلة أو logs.

## معايير الإكمال

لا يكتمل المنهج إلا عندما يكون لكل دليل عام snippet تنفيذي أو متحقق من المصدر، ولكل وحدة precondition وartifact متوقع، ويبنى مثال Workbench من تثبيت نظيف، ويعكس الموقع الرسمي العقود نفسها في الإصدار الحالي. تقارن مراجعة الإصدار بين أوامر وsnippets التوثيق الداخلي والموقع وتمنع الإصدارات القديمة والادعاءات غير المدعومة.
