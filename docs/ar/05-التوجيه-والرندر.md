# 05 — التوجيه والرندر وطرق توليد الصفحات

## التوجيه القائم على الملفات

يكتشف Nexis ملفات `src/routes` ويحوّلها إلى URL. الاسم `index.tsx` يمثل مجلد المسار، والاسم العادي يمثل مسارًا، والأقواس المربعة تمثل parameter ديناميكيًا.

```text
src/routes/index.tsx                 → /
src/routes/about.tsx                 → /about
src/routes/docs/index.tsx            → /docs
src/routes/docs/[slug].tsx           → /docs/:slug
src/routes/shop/[id]/index.tsx       → /shop/:id
```

استخدم أسماء صغيرة وواضحة. لا تجعل route واحدًا مسؤولًا عن منطق كل الموقع.

## RouteRecord وRouteMatch

يقوم Router بإنشاء `RouteRecord` يحتوي على نمط المسار، parameters، ومرجع الملف. عند وصول pathname، تنتج `RouteMatch` بقيم parameters. لا تستخرج parameter يدويًا من string إذا كان Router يوفره.

```ts
const match = matchRoute(route, '/docs/architecture')
if (match) {
  console.log(match.params.slug)
}
```

## تنقل `Link` الدلالي

استورد `Link` من `@mohammedaydan/router` عندما تريد أن يختار route تنقل same-origin تدريجيًا. يخرج الخادم وSSG رابط `<a href>` عاديًا؛ لذلك تتبع محركات البحث وbookmarks ونسخ الرابط والمتصفحات بلا JavaScript نفس تنقل المستند الأصلي.

```tsx
import { Link } from '@mohammedaydan/router'

export default function DocumentationIndex() {
  return (
    <nav aria-label="Documentation">
      <Link href="/docs/architecture" prefetch="intent">
        اقرأ المعمارية
      </Link>
      <Link href="/docs/reference" prefetch="viewport" transition={false}>
        مرجع API
      </Link>
    </nav>
  )
}
```

يخرج البناء `nexis-navigation.js` فقط عند وجود Link في HTML الناتج. يعترض runtime النقرات الأساسية غير المعدلة على anchors المعلّمة داخل نفس origin، ويجلب مستند HTML عاديًا، ويتحقق من `#app`، ويحدّث metadata التي يملكها، ثم يستبدل هذا outlet فقط. يستخدم History API واستعادة scroll ويمكنه استخدام `document.startViewTransition()` عندما يدعمه المتصفح. هذا استبدال DOM مباشر، وليس Virtual DOM diff أو client component renderer.

تحتفظ modified clicks وmiddle clicks وexternal origins و`target` و`download` و`rel="external"` والأحداث الممنوعة سابقًا وروابط hash داخل المستند بسلوك المتصفح الأصلي. أي فشل fetch أو استجابة غير HTML أو outlet مفقود أو تنقل غير مكتمل يعود إلى navigation عادي. يمكن لـ`prefetch="intent"` حفظ استجابة عامة بعد hover أو focus، بينما يستخدم `viewport` `IntersectionObserver`؛ ولا تحفظ الاستجابات `private` أو `no-store` أبدًا.

> Link لا يحول route إلى تطبيق client-only. اجعل كل وجهة صحيحة وحدها كـSSR/SSG HTML، ولا تضع أسرارًا داخل output المرندر أو أصول state العامة.

## المسارات الديناميكية

للمسارات التي يجب توليدها وقت البناء، وفر قائمة static paths. مثال مفاهيمي:

```tsx
export async function getStaticPaths() {
  const slugs = await getDocumentationSlugs()
  return slugs.map((slug) => ({ params: { slug } }))
}

export default async function DocumentationPage({ params }: { params: { slug: string } }) {
  const page = await getDocumentationPage(params.slug)
  if (!page) return <NotFound />
  return (
    <article>
      <h1>{page.title}</h1>
      {page.content}
    </article>
  )
}
```

يجب أن تكون القيمة قابلة للتنبؤ وآمنة. لا تسمح بأن ينتج parameter مسارًا خارج مجلد الإخراج.

## أوضاع الرندر

| الوضع    | الاستخدام                                           | Cache                             |
| -------- | --------------------------------------------------- | --------------------------------- |
| `static` | صفحة لا تعتمد على Request أو بيانات لحظية           | يمكن تخزين HTML بشكل قوي          |
| `server` | صفحة تعتمد على headers أو cookies أو بيانات لكل طلب | لا تستخدم shared cache افتراضيًا  |
| `isr`    | صفحة يمكن إعادة توليدها بعد مدة                     | تحتاج cache adapter و`revalidate` |

### Static

استخدمه للصفحات التسويقية، المقالات، التوثيق، وصفحات المنتجات التي تتغير عند البناء.

### Server

استخدمه للصفحات التي تعتمد على المستخدم الحالي أو Request headers. لا تجعل HTML يحتوي بيانات مستخدم ثم تضع له `public, immutable`.

### ISR

ISR يحتاج عقد cache واضحًا. يجب أن يحدد التطبيق من يخزن HTML، مدة `revalidate`، وسلوك الفشل. لا تستخدم ISR مع بيانات حساسة دون فصل key حسب المستخدم.

## `renderRoute`

تقبل واجهة الرندر route input مع `mode`. القاعدة الأمنية المهمة أن وضع `server` يمنع shared caching، ووضع `isr` يرفض العمل دون cache adapter مناسب.

```ts
const result = await renderRoute({
  mode: 'static',
  request: new Request('https://example.com/'),
  render: () => <Home />,
})
```

راجع تعريف `RouteRenderInput` و`RenderOutput` في `packages/renderer/src/modes.ts` عند كتابة Adapter مخصص.

## 404 و405 وHEAD

يجب أن يملك التطبيق route 404 أو أن يعتمد على 404 الافتراضي للخادم. `GET` يعيد body، بينما `HEAD` يعيد نفس headers دون body. الطرق غير المدعومة يجب أن تعيد `405` و`Allow` مناسبًا بدل تنفيذ route كأنها GET.

## Streaming

`renderToStream` يعيد `ReadableStream<Uint8Array>`. استخدمه عندما يكون HTML كبيرًا أو توجد أجزاء async. حدّد flush threshold، وتعامل مع AbortSignal. لا تترك Promise أو producer يعمل بعد إغلاق الاتصال.

```ts
const stream = renderToStream(<Page />, {
  signal: request.signal,
  flushThreshold: 1024,
})
return new Response(stream, {
  headers: { 'content-type': 'text/html; charset=utf-8' },
})
```

## Cache headers

HTML يحتاج عادة إلى `public, max-age=0, must-revalidate` أو سياسة مناسبة للتطبيق. الأصول fingerprinted يمكن أن تستخدم `public, max-age=31536000, immutable`. لا تضع Cache عامة على استجابة تتضمن بيانات مستخدم أو cookies خاصة.

## أفضل تقسيم

اجعل Route يحدد «ماذا نعرض»، وComponent يحدد «كيف نعرض»، وData layer يحدد «من أين نأتي بالبيانات»، وServer/Action layer يحدد «ما الذي يمكن تغييره». هذا الفصل يقلل أخطاء cache ويجعل اختبار كل طبقة مباشرًا.
