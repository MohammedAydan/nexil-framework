# 03 — إنشاء مشروع Nexis بالإصدار الأحدث

## المتطلبات

يحتاج المشروع إلى Node.js حديث يدعم ESM وTypeScript، وpnpm. الإصدار المثبت في مستودع Nexis وقت كتابة هذا الدليل هو Node `22.13.0` وpnpm `10.15.0`. استخدم نسخة LTS حديثة متوافقة مع بيئة CI لديك، وثبّت مدير الحزم ضمن الفريق لتجنب اختلاف lockfile.

```bash
node --version
pnpm --version
```

## إنشاء مشروع

يوفر المستودع حزمتين لإنشاء المشاريع: `@mohammedaydan/create-nexis-app` و`@mohammedaydan/create-nexis`. استخدم الـ CLI المنشور أو نفّذ الحزمة من workspace في أثناء تطوير الفريمورك.

```bash
pnpm dlx @mohammedaydan/create-nexis-app my-site
cd my-site
pnpm install
```

إذا كان لديك إصدار قديم من CLI، لا تخلط ملفات `dist` القديمة مع الحزمة الجديدة. احذف مجلد المشروع التجريبي أو أعد إنشاءه من الإصدار المستهدف ثم ثبّت dependencies من جديد.

## قوالب البداية

يوفر منشئ v1.3.1 ثلاثة قوالب مختلفة بوضوح، مع بقاء `interactive` هو القالب الافتراضي للتوافق مع تجربة الإنشاء السابقة.

| القالب        | الخيار                   | النتيجة                                                                               |
| ------------- | ------------------------ | ------------------------------------------------------------------------------------- |
| `minimal`     | `--template minimal`     | route ثابت HTML-first بلا حدود تفاعل.                                                 |
| `interactive` | `--template interactive` | صفحة SSR مع حد `onClick$` صغير قابل للاستئناف؛ وهو الافتراضي.                         |
| `secure-node` | `--template secure-node` | بداية ثابتة مع `securityHeaders` صريح وسياسة CSP بداية للمراجعة و`trustProxy: false`. |

```bash
pnpm dlx @mohammedaydan/create-nexis@1.3.1 portal --yes --ts --template secure-node
```

تولّد القوالب حزمة `@mohammedaydan/starter` عبر الدالة المكتوبة `createStarterFiles()`. تعيد هذه الدالة قائمة ملفات نسبية فقط؛ لا تكتب في نظام الملفات ولا تثبت packages ولا تنشئ archive ولا تتصل بالشبكة ولا تتعامل مع credentials. لذلك يمكن أن يستخدم CLI ومنشئ مشروع داخل المتصفح نفس العقد بلا تباعد.

## البنية الموصى بها

```text
my-site/
├── src/
│   ├── routes/
│   │   ├── index.tsx
│   │   ├── about.tsx
│   │   └── docs/
│   │       └── [slug].tsx
│   ├── components/
│   ├── lib/
│   └── styles/
├── public/
├── nexis.config.ts
├── package.json
├── tsconfig.json
└── pnpm-lock.yaml
```

لا تضع منطق قاعدة البيانات داخل ملفات المكونات. ضع الوصول إلى البيانات في `src/lib/server` أو طبقة مشابهة، ثم مرر النتائج إلى Route أو Component.

## أول صفحة

```tsx
// src/routes/index.tsx
import { renderHead } from '@mohammedaydan/seo'

export default function Home() {
  return {
    type: 'html',
    props: {
      lang: 'ar',
      children: [
        {
          type: 'head',
          children: [
            renderHead({
              title: 'موقعي باستخدام Nexis',
              description: 'صفحة HTML أولًا مبنية باستخدام Nexis.',
            }),
          ],
        },
        {
          type: 'body',
          children: [{ type: 'h1', children: ['مرحبًا من Nexis'] }],
        },
      ],
    },
  }
}
```

في المشاريع التي تستخدم JSX runtime، يكون المكون أبسط عادة:

```tsx
export default function Home() {
  return (
    <main>
      <h1>مرحبًا من Nexis</h1>
    </main>
  )
}
```

## إعداد `nexis.config.ts`

```ts
import type { NexisBuildConfig } from '@mohammedaydan/cli'

const config: NexisBuildConfig = {
  siteOrigin: 'https://example.com',
  feed: {
    title: 'موقعي',
    description: 'آخر الصفحات والتحديثات.',
    language: 'ar',
  },
  redirects: [{ from: '/old-docs', to: '/docs/architecture', status: 308 }],
}

export default config
```

استخدم `siteOrigin` حقيقيًا في الإنتاج. لا تعتمد على اسم المضيف المؤقت في بيئة preview عند توليد canonical أو sitemap.

## أوامر التطوير

| الأمر                | الوظيفة                                     |
| -------------------- | ------------------------------------------- |
| `pnpm dev`           | تشغيل خادم التطوير إن كان معرفًا في المشروع |
| `pnpm build`         | بناء كل workspace أو المشروع                |
| `pnpm typecheck`     | فحص TypeScript بالمراجع                     |
| `pnpm test`          | تشغيل Vitest                                |
| `pnpm test:e2e`      | تشغيل Playwright                            |
| `pnpm lint`          | تشغيل ESLint                                |
| `pnpm format:check`  | فحص Prettier                                |
| `pnpm release:check` | محاكاة نشر الحزم دون نشر فعلي               |

## أول تحقق

بعد إنشاء المشروع شغّل:

```bash
pnpm build
pnpm typecheck
pnpm lint
pnpm test
```

لا تنتقل إلى النشر إذا كانت هناك تحذيرات TypeScript أو فرق تنسيق. في Nexis قد يعني خطأ في build أن route أو chunk أو asset لن يصل إلى `dist` بالشكل المتوقع.

## تحديث الإصدار

حدّث dependencies من مصدر واحد، ثم راجع lockfile وشغّل اختبارات المشروع. لا تستخدم `latest` في تطبيق إنتاج دون تثبيت الإصدار في lockfile. عند الانتقال بين إصدارات رئيسية، اقرأ [دليل الترقية](./19-الإصدارات-والترقية.md).
