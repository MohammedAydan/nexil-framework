# 17 — أفضل الممارسات

## تصميم الصفحة

ابدأ من HTML الذي يجب أن يصل في أول استجابة، ثم أضف التفاعل كحدود صغيرة. لا تجعل المكون interactive لمجرد أن الصفحة تحتوي على زر واحد.

## اختيار render mode

استخدم static متى كانت البيانات قابلة للبناء، server للبيانات الخاصة بالطلب، وISR للبيانات العامة التي تحتاج تحديثًا دوريًا. القرار يجب أن يسبق كتابة cache headers.

## المكونات

اجعل component API صغيرًا ومكتوبًا بالأنواع. استخدم عناصر HTML الدلالية، وأخرج loading/error/empty states صراحة. لا تضع database calls في مكون يمكن أن يدخل client bundle.

## التفاعلية

- استخدم `$` فقط للـ handlers التي يجب أن تكون lazy.
- اترك progressive enhancement native.
- مرر values قابلة للتسلسل فقط.
- حرر Signals وStores وEffects.
- اختبر الشبكة قبل وبعد التفاعل.

## الحالة

احسب القيم المشتقة بدل تخزينها مرتين. استخدم `batch` للمعاملات، وتجنب global singleton في SSR، وافحص Computed cycles. اربط كل Store بعمر واضح.

## Actions

تحقق في الخادم، افحص authorization بعد validation، استخدم Origin/CSRF، وطبّق Idempotency للعمليات القابلة للتكرار. لا تسجل body أو secrets.

## CSS

استخدم logical properties، وراجع RTL وfocus وreduced motion. اجعل CSS قابلًا للاستخراج، ولا تشحن JavaScript لتغيير class بسيط يمكن عمله بـ CSS.

## الصور

أنشئ variants تناسب widths، استخدم picture وalt وأبعادًا صريحة، وفعّل persistent cache في build متكرر. لا تجلب صورًا خارجية بلا allowlist.

## SEO

كل route منشور يحتاج title وdescription وcanonical. JSON-LD يجب أن يطابق المحتوى، وsitemap/feed لا يجب أن يحتوي مسارات لا يمكن الوصول إليها. لا تخلط نتائج Lighthouse مع rankings.

## الأداء

حافظ على Bootstrap صغيرًا، وراقب chunks والـ HTML والـ CSS. قارن route equivalent فقط. اذكر بيئة القياس وحدوده. استخدم server timing وreal-user telemetry عند توفر governance.

## الأمان

افترض أن كل client code مكشوف. ضع secrets على الخادم، ارفض protocols الخطرة، امنع traversal، حد body، وثق proxy trust. نفذ dependency audit ومراجعة lockfile.

## الاختبارات

لكل feature جديد أضف:

1. Unit test للمنطق.
2. Integration test للعقد بين الحزم.
3. E2E إذا ظهر في المتصفح أو HTTP.
4. Benchmark إذا أثر على bytes أو latency.

## التوثيق

وثّق القرار والحدود وليس طريقة الاستخدام فقط. اذكر ما لا يدعمه الفريمورك حتى لا يبني المستخدمون افتراضًا خاطئًا.
