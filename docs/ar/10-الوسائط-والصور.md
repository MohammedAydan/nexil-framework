# 10 — الصور والوسائط

## خط أنابيب الوسائط

حزمة `@mohammedaydan/media` توفر بناء variants بأحجام وصيغ مختلفة، مع cache مبني على hash. يمكن لـNexis تشغيل الخط تلقائيًا لصور PNG وJPEG وSVG العامة أثناء `nexis build`، لكنه يظل opt-in حتى لا تتغير مخرجات التطبيقات الحالية قبل أن تختاره صراحة.

```ts
// nexis.config.ts
import { defineConfig } from '@mohammedaydan/serve'

export default defineConfig({
  media: {
    images: {
      transform: true,
      widths: [320, 640, 960, 1280],
      cacheDir: '.nexis/media-cache',
    },
  },
})
```

ينسخ الـbuild الملف العام الأصلي ثم ينشئ AVIF وWebP بجواره، ويحتفظ بنتائج قابلة لإعادة الاستخدام تحت `.nexis/media-cache`، ويكتب `nexis-media.json` داخل `dist/` و`dist/client/`. أضف `.nexis/` إلى `.gitignore`؛ فالـcache قابل للحذف وليس artifact مصدر.

لملف `public/images/hero.jpg` ستكون من الملفات الناتجة `/images/hero-jpg-320.avif` و`/images/hero-jpg-320.webp` و`/images/hero-jpg-640.avif` وهكذا. اعرض النتيجة وحالة الـcache عبر `nexis analyze`.

## Picture markup

عندما تريد responsive image، استخدم `<picture>` مع AVIF ثم WebP ثم fallback. يجب أن يحتوي `<img>` على `alt` و`width` و`height` أو `aspect-ratio` لتقليل layout shift.

```tsx
<picture>
  <source srcSet="/images/hero-640.avif" type="image/avif" />
  <source srcSet="/images/hero-640.webp" type="image/webp" />
  <img src="/images/hero-640.jpg" width="640" height="360" loading="lazy" alt="وصف دقيق للصورة" />
</picture>
```

استخدم `loading="eager"` و`fetchpriority="high"` فقط لصورة LCP الحقيقية. لا تجعل كل الصور eager.

عند استعمال ملفات build الثابتة، فضّل مكوّن `Image` مع `staticVariants`. يستخدم نفس عقد التسمية الذي يستخدمه `nexis build`:

```tsx
import { Image } from '@mohammedaydan/media'

export default function Hero() {
  return (
    <Image
      src="/images/hero.jpg"
      width={1280}
      height={720}
      alt="مساحة عمل المنتج"
      widths={[640, 960, 1280]}
      sizes="(max-width: 760px) 100vw, 56vw"
      priority
      staticVariants
    />
  )
}
```

`staticVariants` اختيار صريح. Nexis لا يعيد كتابة `<img>` أو `<picture>` المكتوبة يدويًا، لذلك تستطيع ترقية كل Route تدريجيًا والاحتفاظ بالتحكم في fallback.

## Cache

الـ in-memory cache سريع لكنه يختفي مع restart. `cacheDir` يسمح بإعادة استخدام النتائج بين عمليات build. يجب أن يكون cache قابلًا للحذف، ولا يعتبر مصدر الحقيقة. لا تضع ملفات cache داخل `public` إلا إذا كانت مقصودة كأصول منشورة.

احسب cache key من bytes المصدر، العرض، الصيغة، وإعدادات التحويل. إذا تغيرت إعدادات الجودة ولم تدخل في key، قد تحصل على نتيجة قديمة.

يضم Nexis bytes المصدر وfile base وقائمة العروض داخل cache key. احذف `.nexis/media-cache` لفرض بناء كامل، ولا تنشر هذا المجلد.

## صور خارجية

لا تسمح بعنوان صورة من المستخدم أن يتحول إلى fetch خادمي بلا allowlist. ضع بروتوكولات HTTP(S) فقط، وحدد hosts، وحجمًا أقصى، وtimeout، وعدد redirects. عالج SSRF كخطر حقيقي عند جلب صور من الخادم.

## OG images

حزمة `@mohammedaydan/og-image` تولد SVG آمنًا ثم PNG في build. العناوين تُهرب قبل إدخالها إلى SVG، والملف الناتج content-addressed.

```ts
const card = await generateOgImage({
  title: 'عنوان الصفحة',
  description: 'وصف مختصر',
  outputDir: './dist/client/og',
})
```

لا تجعل OG generation جزءًا من client bundle. لا تعرض endpoint ديناميكيًا يستقبل SVG خام من المستخدم دون sanitization.

## Alt text

`alt` ليس مكانًا لتكرار keyword. اكتب ما يحتاجه المستخدم الذي لا يرى الصورة. الصورة الزخرفية تستخدم `alt=""`. الصورة التي تحمل معلومة يجب أن تنقل تلك المعلومة في النص البديل.

## أداء الصور

| القرار          | التوصية                              |
| --------------- | ------------------------------------ |
| أول صورة مرئية  | قياس أبعاد صريحة وpreload عند الحاجة |
| صور أسفل الصفحة | lazy loading                         |
| الصيغة          | AVIF ثم WebP ثم fallback             |
| العرض           | لا ترسل 2000px إلى شاشة 320px        |
| التخزين         | immutable للأسماء ذات hash           |
| الفشل           | fallback واضح وتحذير في build        |

## التحقق

افحص أن كل variant غير فارغ، وأن filenames آمنة، وأن `content-type` صحيح، وأن صورة fallback موجودة، وأن صفحة بلا صورة لا تشير إلى ملف غير موجود. راقب LCP وCLS في Lighthouse، لكن لا تقدم نتائج المختبر كأنها بيانات مستخدمين حقيقيين.
