# 16 — استكشاف الأخطاء

## خطأ `tailwind-merge` أو workspace link

قد يترك fixture مؤقت symlink يشير إلى مسار خارج workspace. افحص:

```bash
ls -l packages/css/node_modules/tailwind-merge
pnpm install --offline --no-frozen-lockfile
pnpm --filter @mohammedaydan/css build
```

لا تعدل import في source لإخفاء مشكلة تثبيت محلية.

## الصفحة تعيد 404

تحقق من:

1. أن الملف داخل `src/routes`.
2. أن اسم `index.tsx` صحيح.
3. أن parameter الديناميكي له static paths عند SSG.
4. أن build أُعيد بعد إضافة route.
5. أن production server يشير إلى `dist/client` الصحيح.

## chunk لا يعمل بعد النقرة

افحص HTML وattributes وbootstrap:

```bash
curl -sS http://localhost:4173/
grep -R "nexis-chunks" dist/client
```

تأكد من أن `data-nx-on-*` يشير إلى chunk موجود، وأن base يستخدم script-relative URL عند وجود `document.currentScript`.

## النموذج ينتقل بدل أن يبقى في الصفحة

هذا غالبًا event-order issue. يجب أن يمنع bootstrap submit synchronously قبل انتظار import، ثم ينفذ action. احتفظ بـ `action` و`method` native كـ fallback، وتحقق أن selector/attribute الخاص بالنموذج صحيح.

## `Forbidden origin`

السبب المعتاد أن المتصفح يرسل Origin HTTPS عام بينما dev server يبني Request على HTTP داخلي. في preview خلف proxy:

```bash
NEXIS_TRUST_PROXY=1 NEXIS_HOST=0.0.0.0 pnpm dev
```

لا تفعّل هذا على server مكشوف إلا إذا كان proxy ينظف forwarded headers.

## Cache غير صحيح

إذا ظهر محتوى مستخدم لمستخدم آخر، راجع mode وCache-Control فورًا. server mode لا يجب أن يملك shared cache عام. تأكد أن cache key يتضمن كل المدخلات المؤثرة.

## `computed cycle detected`

ابحث عن Computed يقرأ نفسه أو Computed آخر يعود إليه. افصل القراءة عن الكتابة، ولا تحدث Signal أثناء getter. استخدم Effect منفصلًا للـ side effect.

## `Deno executable not found`

Node strip-types ليس تنفيذ Deno. ثبّت Deno في CI أو استخدم بيئة Deno حقيقية وشغّل:

```bash
pnpm test:deno:e2e
```

سجّل بوضوح أي fallback محلي بدل ادعاء نجاح Deno.

## Lighthouse يفشل

افحص التقرير JSON وليس score فقط. الأسباب المعتادة: صورة LCP كبيرة، contrast، title ناقص، canonical خاطئ، JavaScript غير ضروري، أو server قديم على port نفسه. استخدم port معزولًا، وأوقف servers قديمة.

## feed أو sitemap ناقص

تأكد من أن dynamic paths توسعت فعلًا، وأن `siteOrigin` صحيح، وأن route record يدخل feedItems. افحص `feed.xml` و`atom.xml` و`nexis-manifest.json` بعد build.

## Redirect يتبع تلقائيًا في fetch

استخدم:

```ts
fetch(url, { redirect: 'manual' })
```

وإلا قد ترى الصفحة النهائية بدل status `308`.

## Build يفشل بسبب config

JSON غير صالح يجب أن يفشل بوضوح. إذا كان لديك `nexis.config.json` خاطئ، لا تتوقع أن يسقط النظام بصمت إلى `.ts`. أصلح الملف أو احذفه. في TypeScript config، اجعل `default export` object صالحًا.

## Edge handler لا يخدم asset

تحقق من leading slash، MIME، method `GET/HEAD`، ووجود fallback. Deno/Cloudflare لا يملكان افتراضات Node نفسها؛ افصل filesystem code عن Fetch handler.

## الاختبارات تعلق

أوقف processes القديمة، افحص ports، وتأكد أن fixture cleanup يعمل. استخدم `ps`, `ss -ltnp`، ثم أعد التثبيت إذا تغيرت workspace links.

## طريقة التشخيص

ابدأ بأصغر reproduction، احفظ HTTP status والheaders والbody، ثم اختبر طبقة واحدة. لا تقفز مباشرة إلى تغيير compiler أو bootstrap قبل التأكد من HTML الناتج.
